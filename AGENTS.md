# Project working rules
- Build Atelier for creative studios coordinating real client engagements. Keep its warm editorial visual identity distinct and uncluttered.
- Each day, read this file, BACKLOG.md and Git status, review prior code and the previous diff, then debug open issues before today's feature.
- Always include code review, behavior-focused tests, the day's ticket, documentation/backlog updates, debugging and a final regression review. Run test, typecheck and build after installing dependencies.
- Preserve task ownership, priority, due-date meaning and stage transitions. Do not show fictional sample tasks as live client data.
- Keep phone, tablet and desktop usable; provide keyboard-accessible alternatives for board drag actions; support light/dark themes and reduced motion.
- Use React, TypeScript, Vite, Tailwind CSS and React Icons. Keep task models typed and UI components small.
- Update BACKLOG.md daily with status, bugs found, new work and the next day's exact scope.
- Keep .npmrc ignored and local. Never commit tokens, private client details, .env files or build output. Never force-push or rewrite history.
- Work only in this repository. Create descriptive day branches and meaningful commits after relevant checks pass.
